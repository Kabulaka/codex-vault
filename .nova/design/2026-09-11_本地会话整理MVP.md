## 1. 共享约束

### 1.1 问题与成功结果

| 问题 | 成功结果 |
|------|----------|
| Codex 缺少一个能按用户指定时间安全整理本机交互会话、且不会误伤活动任务或泄露正文的通用工具 | 用户可在 Linux 与 macOS 的双语 TUI 中筛选完整会话树，预览后归档、恢复或受控删除，并从重扫和本地记录核对真实结果 |

### 1.2 共享契约

| 契约 | 语义键 | 唯一规则 |
|------|--------|----------|
| S-01 | 共享/Codex状态权威 | Codex 会话及其状态只通过每次启动的本地 `codex app-server` stdio JSONL 协议读取或改变，禁止读取内部数据库、直接操作会话文件或推断未观察到的状态。 |
| S-02 | 共享/操作对象 | 一个可管理的交互根会话及其全部派生会话构成不可拆分的树；筛选、保护判断、预览、确认和结果核对都以整树为单位。 |
| S-03 | 共享/最小数据 | 会话发现、搜索、展示和记录只可使用标题、会话 ID、项目、工作目录、归档状态、固定状态、运行状态、时间与父子关系，不读取、索引、搜索或保存消息正文。 |

## WP-01 本地会话整理 MVP

### 契约

| 契约 | 维度 | 语义键 | 唯一规则 |
|------|------|--------|----------|
| WP-01-C01 | 交付边界 | MVP/交付范围 | 本期交付 Rust 2024 单二进制双语 TUI、本地 app-server 能力探测、元数据分页扫描、会话树筛选与预览、归档、恢复、受控永久删除、SQLite 偏好和操作记录，以及 GitHub Releases 四目标构建和 SHA-256；不交付 Windows、远程连接、无人值守批处理、网络 API、WebSocket、后台服务、正文搜索、Codex 缓存日志插件配置认证历史清理、自动更新、crates.io 发布或 macOS 签名公证。 |
| WP-01-C02 | 参与者与权限 | MVP/本机用户 | 工具只管理启动它的当前操作系统用户可由 app-server 发现的会话；不提升权限、不切换用户、不访问远端会话。 |
| WP-01-C03 | 触发与输入 | 扫描/启动输入 | 每次启动均创建并初始化一个本地 app-server 子进程，分页扫描活动与已归档会话，再加载本地偏好形成首次只读视图；启动参数不提供绕过交互确认的写入口。 |
| WP-01-C04 | 触发与输入 | 扫描/能力门禁 | 运行时探测 `thread/list`、`thread/read`、`thread/archive`、`thread/unarchive`、`thread/delete`、状态字段和祖先关系能力；目标操作能力缺失、来源无法可靠分类或关系不完整时关闭全部写操作并展示具体原因。 |
| WP-01-C05 | 结果、状态与不变量 | 会话/来源资格 | 只有来源字段明确证明为交互式根任务的会话树进入可操作集合，其派生节点随根任务纳入；独立 `codex exec` 非交互根记录默认排除且不能被选择。 |
| WP-01-C06 | 触发与输入 | 筛选/时间条件 | 首次时间阈值为 30 天，后续使用最近一次成功保存的条件；提供滚动 24 小时的 `1d`、`7d`、`30d` 和自定义绝对截止时间，整树年龄取所有节点最后活动时间的最大值。 |
| WP-01-C07 | 触发与输入 | 筛选/元数据条件 | 默认查看全部项目；用户可按项目、工作目录、标题、会话 ID、归档状态和 WP-01-C06 的时间条件组合筛选，所有结果初始均不选中。 |
| WP-01-C08 | 结果、状态与不变量 | 会话/保护门禁 | 树内任一节点处于 pinned、运行、排队、等待交互或未知状态即阻止整树写操作；pinned 只提示用户先在 Codex 中取消固定并重新扫描，不由本工具隐式解除。 |
| WP-01-C09 | 结果、状态与不变量 | 计划/预览确认 | 写操作前只读展示完整树的允许字段、匹配与排除原因、动作及影响数量；确认后立即重读整树，成员或状态相对预览发生漂移即废弃计划并要求重新预览。 |
| WP-01-C10 | 结果、状态与不变量 | 记录/预写门禁 | 每次写操作必须先在自有 SQLite 事务中持久化不可变批次及逐节点计划；数据库不可写、迁移失败或计划落盘失败时不得调用任何 Codex 写接口。 |
| WP-01-C11 | 结果、状态与不变量 | 操作/顺序与核对 | 归档和永久删除按后代优先、恢复按根优先执行；每步响应和通知只作观测证据，批次结束必须重扫活动与归档集合，以重扫所得逐节点状态形成实际结果。 |
| WP-01-C12 | 结果、状态与不变量 | 删除/强确认 | 永久删除只允许完整树全部处于已归档状态且不存在未归档派生节点；用户必须输入预览中的准确删除数量，数量不匹配时不执行。 |
| WP-01-C13 | 结果、状态与不变量 | 记录/保留期 | SQLite 只保存筛选偏好、不可变批次和时间、动作、会话 ID、结果等允许字段；操作记录默认保留 90 天，保留期清理不得改变 Codex 状态。 |
| WP-01-C14 | 结果、状态与不变量 | TUI/交互与退出 | TUI 提供树列表与筛选、详情与保护原因、操作预览、结果与历史四类主视图及中英切换；正常退出、错误和中断路径均恢复终端。 |
| WP-01-C15 | 结果、状态与不变量 | 发布/可验证产物 | GitHub Releases 构建 Linux x86_64、Linux ARM64、macOS Intel 和 macOS Apple Silicon 四个产物并生成 SHA-256 校验文件，许可证为 MIT。 |
| WP-01-C16 | 失败与恢复 | 执行/部分失败 | 单节点失败、app-server 返回成功但通知或后代状态不完整、进程中断及崩溃均不得回滚或虚构 Codex 状态；保留已发生结果，把未确认结果标为失败或中断，重扫后允许用户基于真实状态重试。 |
| WP-01-C17 | 失败与恢复 | 连接/不可用 | app-server 启动、初始化、协议解析或会话发现失败时展示可执行诊断方向，保持 Codex 状态不变，并仍保证子进程清理和终端恢复。 |
| WP-01-C18 | AI 决策边界 | 实施/变更权限 | 实施可自行决定不改变上述外部行为的内部函数拆分、终端配色、局部组件、查询实现与测试组织；修改需求语义、扩大持久化字段、绕过 app-server、改变保护或确认门禁、增加平台渠道或显著运行依赖必须重新取得用户确认。 |

### 验收

| 覆盖契约 | 场景 | 预期结果 |
|----------|------|----------|
| S-01、S-03、WP-01-C02、WP-01-C03 | 在 Linux 与 macOS 模拟环境启动并扫描同时含活动和归档记录的数据集 | 仅通过 app-server 分页得到当前用户允许元数据，未读取正文或内部存储，也没有非交互写入口。 |
| S-02、WP-01-C05、WP-01-C06、WP-01-C07 | 数据集含交互根任务、派生任务、独立 `codex exec`、跨项目记录及恰好位于 24 小时边界的节点 | 只生成完整交互任务树；独立 exec 不可选；树龄、组合筛选、全部项目默认值和默认全不选符合契约。 |
| WP-01-C04、WP-01-C08 | 分别移除祖先关系能力、制造断裂父子关系，并令树内节点处于各受保护状态 | 能力或关系不可靠时全局只读；任一保护节点阻止整树操作并给出稳定原因，pinned 不被隐式修改。 |
| WP-01-C09、WP-01-C10 | 完成预览后改变树成员或状态，并分别令 SQLite 只读、迁移失败和计划写入失败 | 漂移计划失效；记录门禁失败时 app-server 未收到任何写请求。 |
| WP-01-C11、WP-01-C16 | mock 分别执行完整成功、单节点失败、归档响应成功但后代未归档及执行中断 | 调用顺序符合动作规则；结果以最终重扫为准，部分完成不冒充整体成功，真实状态可再次重试。 |
| WP-01-C12 | 对包含未归档后代、非全归档树、数量输入错误和合法全归档树请求永久删除 | 前三类零写入；合法树在数量完全匹配后按后代优先删除并重扫确认。 |
| WP-01-C13 | 保存偏好和多批次记录后推进时间并执行保留期维护 | 重新启动采用上次条件；超过 90 天记录被删除且 Codex 会话状态与调用记录不变。 |
| WP-01-C14、WP-01-C17 | 遍历四类主视图并切换中英文，再触发正常退出、协议错误和中断信号 | 可见文本完成切换；所有路径都清理子进程并恢复原终端设置，错误包含诊断方向。 |
| WP-01-C01、WP-01-C15、WP-01-C18 | 执行格式、静态检查、单元与集成测试，并校验发布矩阵、许可证和产物摘要 | MVP 范围全部通过门禁，四目标产物与 SHA-256 配套，不包含排除能力或未经确认的边界扩张。 |
